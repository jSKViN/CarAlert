# 守护进程详解

## 什么是守护进程？

守护进程（Daemon）是一个**后台运行的程序**，它会持续运行并执行特定任务。在 CarAlert 系统中，守护进程负责实时监控车辆抓拍记录。

## 类比理解

想象守护进程就像一个**24小时值班的保安**：
- 每隔1秒查看一次监控屏幕（轮询数据库）
- 发现可疑人员（拉黑车牌）立即报警
- 发现重要访客（关注车牌）立即通知

## 关键代码解析

### 1. 启动初始化

```php
// 获取最后处理的记录ID
$lastProcessedId = checkNewData($conn);
writeLog("初始 last_record_id: {$lastProcessedId}");

// 加载关注/拉黑列表
$watchPlates = getWatchPlates($conn);
$blacklistPlates = getBlacklistPlates($conn);
writeLog("关注车牌数: " . count($watchPlates) . ", 拉黑车牌数: " . count($blacklistPlates));
```

### 2. 检测新数据

```php
function checkNewData($conn) {
    $sql = "SELECT MAX(id) as max_id FROM p_distinguish_log";
    $result = $conn->query($sql);
    $row = $result->fetch_assoc();
    return $row['max_id'] ?? 0;
}
```

**原理**：获取表中最大的ID，新记录的ID一定比这个大。

### 3. 主循环逻辑

```php
while (true) {
    // 检查是否需要退出
    if (!file_exists($pidFile)) {
        break;  // PID文件被删除，退出循环
    }
    
    // 获取当前最大ID
    $currentLastId = checkNewData($conn);
    
    // 发现新数据
    if ($currentLastId > $lastProcessedId) {
        writeLog("检测到新的车辆抓拍记录 (ID: {$currentLastId})");
        
        // 获取新记录详情
        $newRecords = getRecordsAfterId($conn, $lastProcessedId);
        
        // 处理每条记录
        foreach ($newRecords as $record) {
            processRecord($record);
        }
        
        // 更新已处理ID
        $lastProcessedId = $currentLastId;
    }
    
    // 等待1秒
    sleep(POLL_INTERVAL);
}
```

### 4. 记录处理流程

```php
function processRecord($record) {
    $plateNumber = $record['plate_number'];
    
    // 1. 检查是否是拉黑车牌（优先处理）
    if (isset($blacklistPlates[$plateNumber])) {
        writeLog("拉黑车牌预警触发: {$plateNumber}");
        sendBlacklistAlert($record, $blacklistPlates[$plateNumber]);
    }
    
    // 2. 检查是否是关注车牌
    if (in_array($plateNumber, $watchPlates)) {
        writeLog("关注车牌提醒触发: {$plateNumber}");
        sendWatchNotification($record);
    }
}
```

## 常见问题

### Q: 守护进程占用多少资源？
A: 非常少。主要是每秒一次的数据库查询，查询的是索引字段，性能开销极小。

### Q: 如果数据库连接断开怎么办？
A: 守护进程会自动重连。如果重连失败，会记录错误日志并退出。

### Q: 如何停止守护进程？
A: 在运行窗口按 `Ctrl+C`，或者删除 `daemon.pid` 文件。

### Q: 守护进程会漏掉数据吗？
A: 不会。使用 `last_record_id` 机制确保每条记录都被处理。

### Q: 可以同时运行多个守护进程吗？
A: 不可以。通过 `daemon.pid` 文件防止重复启动。

## 性能优化

1. **增量查询**：只查询ID大于 `last_record_id` 的记录
2. **内存缓存**：关注和拉黑列表缓存在内存中，避免频繁查询
3. **连接复用**：数据库连接不频繁断开重连
4. **批量处理**：一次获取所有新记录，减少查询次数
